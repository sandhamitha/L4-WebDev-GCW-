User Profile Page

Technical Description

The document adheres to the standard HTML5 structure, featuring:
- A <!DOCTYPE html> declaration that confirms the use of HTML5
- An <html lang="en"> tag that specifies the language for accessibility purposes
- <meta> tags in the<head> section to ensure proper character encoding and responsive design
- External CSS files linked through <link> tags, which help separate global styles from those specific to profiles

Navigation and Header

The header includes a three-section horizontal navigation bar:
- .main-nav acts as a flex container divided into three parts
- .nav-logo merges an image with text to establish brand identity
- .nav-center offers centrally aligned navigation links
- .nav-right features a call-to-action button styled with .green-power-btn
This navigation design promotes a balanced arrangement of elements across the header while preserving visual hierarchy.

Main Content Structure

The main content employs a card-based layout system:
- .container functions as the primary wrapper for content sections
- .cards and .cards2 are utilized for various card styles throughout the page
- Profile information is organized into separate card sections for enhanced visual clarity

Profile Information Section

The profile section incorporates:
- .profile-picture for the user's image, likely styled with CSS to achieve a circular shape
- .profile-info for presenting personal details, using appropriate hierarchy with <h1> and <p> tags

Content Cards with Flexible Layout

The "Areas of Interest" section illustrates:
- .cards-container, which creates a flexible grid layout
- .card elements that include both images and text content
- A combination of images and text with semantic heading levels (<h3>)

Skills Visualization

The skills section features:
- .skill-bar to create visual progress bars
- .skill-level with inline width styles (e.g., style="width: 80%;") to indicate skill proficiency
This method provides an intuitive visual representation of skill levels.

Calendar Implementation

The availability calendar utilizes:
- An HTML <table> for an organized date display
- The .available class to highlight available dates
- A legend to clarify the meaning of the displayed information.

Accessibility

The profile page has been designed with several accessibility considerations:

  • Proper language attribute (lang="en") in the HTML tag to assist screen readers with pronunciation
  • Semantic HTML structure using appropriate heading levels (h1, h2, h3) to create a logical document outline
  • Alt text for all images to provide descriptions for screen reader users
  • Adequate color contrast between text and background for readability
  • Responsive design that adapts to different screen sizes for users with various devices
  • Form labels properly associated with input fields using the 'for' attribute
  • Table structure with proper headers for the calendar to ensure screen readers can interpret the data correctly
  • Visual indicators for availability in the calendar with supporting text explanation in the legend

Sitemap page

Technical Description

The Sitemap page incorporates several advanced HTML and CSS techniques to create an interactive visual representation of the website structure:

SVG Implementation
The centerpiece of the sitemap is an SVG (Scalable Vector Graphics) element that provides a visual hierarchy of the website's structure:

  • The <svg> tag with defined width and height creates a canvas for the sitemap visualization
  • <rect> elements with rx/ry attributes create rounded rectangle nodes for each page
  • <text> elements position the page names within each rectangle
  • <line> elements connect the nodes to show relationships between pages
  • Wrapping <a> tags around <rect> and <text> elements make the entire node clickable

Visual Hierarchy
The design emphasizes clear visualization of the site structure:

  • Central positioning of the main "WEBSITE--SITEMAP" node at the top
  • Radiating lines connecting to secondary pages
  • Consistent styling of nodes with rounded corners for visual appeal
  • Strategic positioning of elements using x/y coordinates for clean layout

Interactive Elements
The sitemap is functional, not just decorative:

  • Each node serves as a navigation element linked to its corresponding page
  • The SVG is contained within a responsive container (.blocksite) to maintain proper display across devices

Accessibility

The Sitemap page addresses accessibility in several key ways:

  • Proper document structure with semantic HTML elements
  • Text alternatives within SVG elements to ensure content is accessible even if graphics cannot be displayed
  • Clickable areas are sufficiently large to accommodate users with motor control limitations
  • Page uses the lang attribute to identify the language of the content
  • Navigation links are clearly labeled and consistent with the rest of the site
  • SVG elements include appropriate text labels that can be interpreted by assistive technologies
  • Visual connections between site elements are reinforced with text labels, not relying solely on visual connections

Challenges and Lessons Learned

  • Complex Error Resolution: One of the significant challenges was interpreting and resolving complex validation errors. HTML validation errors often provided cryptic messages that required additional research to understand and fix properly. This taught me the importance of methodical debugging and consulting documentation.
  • CSS File Linking Issues: Initially, I struggled with properly linking CSS files due to path reference errors. I learned that relative paths need careful attention, especially when working with nested directory structures. This reinforced the importance of understanding file system organization and the difference between relative and absolute paths.
  • Syntax Variations: I encountered difficulties with the different syntax requirements for linking images versus creating hyperlinks. The subtle differences between src attributes for images and href attributes for links caused unexpected rendering issues. This experience taught me to be precise with HTML syntax and to test links thoroughly before implementation.
  • SVG Implementation: Creating the interactive SVG sitemap was particularly challenging as it required learning a different set of elements and attributes compared to standard HTML. I gained valuable experience with coordinates, shapes, and connecting SVG elements with standard HTML functionality.
  • Responsive Design Balance: Ensuring that pages displayed properly across different screen sizes required careful attention to CSS media queries and flexible layout systems. I learned to test designs across multiple viewports rather than optimizing for a single screen size.

Compliance

The pages I've created adhere to Janet regulations for web page publication through several key implementations:

Accessibility Compliance: All pages implement WCAG 2.1 principles through proper semantic HTML, adequate color contrast, alternative text for images, and keyboard-navigable interfaces. This ensures content is accessible to users with disabilities as required by Janet's digital inclusion policies.

Data Protection: The contact forms include only necessary fields and don't collect excessive personal information, in compliance with data minimization principles. While this is a demonstration site, in a production environment, appropriate privacy notices would be added to comply with UK GDPR requirements that Janet institutions must follow.

Security Considerations: The HTML structure follows security best practices by avoiding inline JavaScript where possible and using external CSS files. Form inputs would require server-side validation in a production environment to prevent injection attacks, as specified in Janet's security guidelines.

Copyright Compliance: All visual assets used are either original creations, properly licensed, or referenced appropriately in the documentation. This respects intellectual property rights as required by Janet's acceptable use policies.

Consistent Navigation: The implementation of consistent headers, footers, and navigation across all pages follows Janet's recommendation for institutional websites to maintain coherent user experience and branding.

Valid Markup: All pages have been validated using W3C validators to ensure standards compliance, which aligns with Janet's emphasis on using established web standards for institutional websites.
